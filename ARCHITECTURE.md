# Architecture

Letterboxd export and MovieLens 32M enter through independent, repeatable ingestion adapters. Source identifiers are retained and mapped into a canonical movie catalog whose preferred external key is TMDB ID. Ambiguous Letterboxd matches remain reviewable instead of being silently accepted.

Processed MovieLens ratings will live in columnar/sparse model artifacts rather than being inserted row-by-row into PostgreSQL. The foundation emits a portable compressed catalog; the training pipeline will choose Parquet when a compatible Arrow runtime is available. PostgreSQL stores the canonical catalog, users, personal interactions, mapping decisions, recommendation events, feedback, and model metadata. pgvector will store semantic movie and review embeddings when Phase 2 begins.

The eventual recommendation path uses multiple bounded candidate generators; independently calibrated collaborative, content, semantic, affinity, quality, novelty, and negative-preference signals; an availability-aware hybrid ranker; diversity reranking; rating/confidence calibration; and explanations grounded only in stored evidence. TMDB-only new releases remain eligible when collaborative coverage is absent.

`backend/app` owns API, configuration, persistence, and orchestration. `ingestion` owns source-specific pure parsing and clients but not transactions. `recommendation` will own candidate generation and ranking. `ml` will own training, evaluation, version manifests, and artifacts.

MovieLens ratings are streamed and materialized as columnar/sparse artifacts because 32 million relational inserts add cost without helping offline training. Personal interactions remain normalized because they need idempotent updates, provenance, feedback joins, and auditability. TMDB matching requires strong title/year agreement and a margin over the runner-up. The initial dimension-free vector column permits model replacement; production indexes will be created for selected fixed dimensions.

Letterboxd ingestion has two persistence stages. `import_runs` fingerprints source archives for run-level audit and safe retries. `import_mappings` is the durable staging record for every source movie, including its personal interaction fields, mapping state, confidence, and candidate evidence. Only a successful mapping creates or updates a canonical movie and `user_movie_interactions` row. This prevents uncertain matches from contaminating training data. TMDB search responses are cached by normalized title/year with expiration, and mapping commits one staged record at a time so interrupted batches resume from pending records.

When Letterboxd contains multiple reviews for the same title/year, the active taste signal is the review with the latest watched date (falling back to export date). Earlier review records do not influence the current taste model. Rewatch counts use Letterboxd diary rows explicitly marked `Rewatch=Yes`; they are not inferred from duplicated import or watched dates.

Manual mapping decisions can only select a TMDB ID from the candidates recorded during matching. Approval creates the canonical interaction with status `matched_manual`; rejection leaves the source data staged but excluded. Each action writes an immutable `mapping_decisions` audit record with actor, reason, prior status, and selected TMDB ID.

MovieLens preparation is deliberately separate from model training. A two-pass reader first discovers exact user IDs and the rating count, then writes disk-backed coordinate arrays and converts them to CSR without holding duplicate Python lists for 32 million ratings. Artifacts include the matrix, exact ID maps, linked catalog, SHA-256 fingerprints, counts, and a deterministic dataset version. Baseline training produces a shrinkage-adjusted popularity model and, when personal coverage permits, a Ridge content model over genre and decade features. These establish comparison floors; they are not evidence of recommendation quality until held-out evaluation runs.

The first collaborative model subtracts shrinkage-adjusted item baselines from observed MovieLens ratings and learns item factors with randomized truncated SVD. Personal integration never retrains the full MovieLens model: it solves a regularized least-squares projection from the user's training ratings into that item-factor space, including a personal intercept. The prototype hybrid averages rating-scale predictions from collaborative, content, and popularity components using explicit versioned weights. The held-out evaluator rebuilds all personal components from the training subset and predicts only hidden ratings, preventing personal-data leakage.
